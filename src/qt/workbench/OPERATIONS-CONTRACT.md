# Workbench operations contract

`qt.workbench.operations.build_operations_router(service)` returns an unprefixed
`APIRouter`. The lead owns `qt.workbench.api` and must include it exactly once
with `prefix="/api/v3"`, replacing that module's older `/datasets`, `/sources`,
and `/runtime` placeholder handlers. It must not include both implementations.

## Construction

Create one shared `ResearchRepository` first, then construct:

```python
operations = OperationsService(
    research_repository=repository,
    state_root=settings.state_root,
    parquet_root=settings.parquet_root,
)
app.include_router(build_operations_router(operations), prefix="/api/v3")
app.state.operations_service = operations
```

The service deliberately receives the shared research repository, state root,
and parquet root. It does not create a second research repository or job queue,
access a production exchange, or enable live execution.

## Routes

All list `limit` values are `1..200`; offset cursors are bounded. `/events/wicks`
requires timezone-aware `from` and `to`, with a maximum 366-day window.

| Route | Effect |
| --- | --- |
| `GET /datasets` | Actual local/managed dataset status, coverage, fingerprint, and quality from `DatasetCatalog`. |
| `GET /sources` | Provider credential/capability state plus local source freshness. `available` means a configured adapter, never that recent valid data exists. |
| `POST /staging/uploads` | Authenticated browser staging upload. The raw body must be CSV (`Content-Type: text/csv`) or Parquet (`application/vnd.apache.parquet` or `application/octet-stream` plus `X-Upload-Format: parquet`). It is incrementally streamed to a task-local temporary file and rejected as soon as it exceeds 1 MiB; it returns an opaque server-created `object_key`. |
| `POST /imports` | Queues a staged CSV/Parquet import. The file is root-contained, size/row limited, schema/time/OHLCV quality checked, fingerprinted, then atomically published by the worker. |
| `POST /sync-jobs` | Queues one public provider adapter/dataset request. `from` and `to` are timezone-aware ISO-8601 timestamps as sent by Web. It uses the provider's real `plan_sync`, `fetch`, and `normalize` signatures—never a generic `fetch_ohlcv` shortcut. |
| `GET /events/wicks` | Computes evidence from persisted OHLCV only. |
| `GET /opportunities` | Reads the persisted scanner snapshot and keeps its stored reason. |
| `GET /portfolio` | Reads persisted paper portfolio ledgers and returns summaries rather than unbounded fills. |
| `GET /runtime`, `POST /runtime/commands`, `GET /audit` | Exposes research/paper state, only pause/resume operations, and immutable audit rows. No live enable/order command exists. |

`POST /imports` and `POST /sync-jobs` require a non-empty `Idempotency-Key`.
The shared `ResearchRepository` transaction stores the request fingerprint and
research job together, so a retry returns the same job while a different payload
using the same key receives 409. `operations.sqlite3` contains audit metadata
only and has no job table.

Web import sequence: send the small raw file body to `/staging/uploads`; use the
returned opaque `object_key` and matching `format` in `POST /imports` with an
idempotency key; then poll the common `/jobs/{job_id}` endpoint. The Worker must
keep the existing 1 MiB request-body ceiling for this route; the origin
independently enforces it without calling `request.body()`. Larger browser
imports require a future streaming/private-R2 pre-signed upload design; the API
must not buffer a larger body or accept a client-selected server path.

## Worker dispatch

The common research worker owns the only claim, attempt lease, heartbeat,
cancellation, recovery, and completion path. Its dispatcher should call
`operations.execute(spec, progress, cancelled)` when `spec["job_type"]` is an
operations type, otherwise dispatch to the existing research executor. This is
the node's single concurrency-one boundary. The dispatch contract is exact:

| `job_type` | Handler | Stored request | Successful result |
| --- | --- | --- | --- |
| `data_import` | `_handle_import` | `source`, `dataset_id`, `format`, `object_key` | Published Parquet path, row count, fingerprint, and quality result. |
| `data_sync` | `_handle_sync` | `source`, `dataset_id`, `symbol`, `timeframe`, `from`, `to` | Published normalized provider Parquet path, row count, fingerprint, and `available_at` quality result. |

A handler receives the durable payload plus common `progress(stage, percent)`
and `cancelled()` callbacks, and returns a JSON-object only after atomic
publication succeeds. The common worker marks the job complete/fails/cancels it;
operations must never claim, fence, or complete a job itself. Unknown job types
are rejected. The shared queue is capped at 20 active jobs.

## Staging and data safety

`object_key` must be the opaque relative key generated by `/staging/uploads`
below `<state_root>/staging` (or the injected `staging_root`). Absolute paths,
traversal, arbitrary URLs, and secret-bearing payloads are rejected. Browser
uploads are capped at 1 MiB; worker imports are capped at 64 MiB / 200,000
rows. CSV and
Parquet input must contain a `timestamp` column and is validated before publish;
timestamps must be unique and increasing,
and OHLCV values must be numeric, non-negative, and internally consistent.

Provider sync is allow-listed against the migrated external-data registry,
bounded to 366 days, validates required fields and `available_at >= timestamp`,
and stores only provider-normalized rows. Every bounded plan item is executed;
a provider plan with gaps, mismatched identity, or more than 32 items is
rejected rather than silently publishing a false full sync. Symbols such as
`BTC/USDT` are canonicalized then injectively encoded for paths, never used as
paths directly. Result quality reports the executed plan-item count and
conservative observed coverage status. Credential status is reported without
credential values; paid/missing providers are not fabricated as zero data.

## Paper controls

The only command keys are `paper.pause` and `paper.resume`; this is the API
contract the Web client must send. They atomically write the existing btc-qt
paper-worker protocol at `control_paper.json` (configurable by injection):
`{"paused": boolean, "ts": epoch_ms}`. The worker reads that exact file and
keeps exits/protection while pausing new entries. `live.enable`, order creation,
flatten, kill, and arbitrary runtime commands are unavailable here. Every
accepted pause/resume records before/after state in the audit store.
